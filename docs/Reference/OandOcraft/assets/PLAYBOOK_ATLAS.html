How the atlas should read

Editorial standard

The atlas should be rich enough to orient a new contributor, with a clear visual hierarchy and enough detail to explain why the planning system exists.

Usage model

Use the atlas to move from high-level orientation into the more specific markdown docs, then use the checklist and walkthrough to execute the work.

What to expect

Each doc should be dense but readable, specific but not noisy, and useful enough that the site feels like part of the product.

What not to expect

Not minimal links, not placeholder prose, and not a thin wrapper around file names.

Sync ruleThe HTML and markdown pages should evolve together. If a doc gains a section, the mirrors should reflect it.
