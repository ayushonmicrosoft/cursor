Library model

The library uses a single record model for everything the app needs to know about a block: display name, category, asset type, source tier, canonical flag, provenance, and source URLs.

Model names are the visible label for now. Brand is intentionally omitted from the UI.
  • Model nameWhat the library shows first.
  • CategoryUsed for grouping and filters.
  • Source tierCanonical, curated, legacy, or fallback.
  • StatusDraft, imported, verified, archived.

Shape system

Quick creators

One-click insert buttons for rectangles, ellipses, lines, arrows, text, and more.

Shape variants

Each creator now carries an explicit variant like triangle, diamond, hexagon, or speech bubble.

Renderer path

Variants are ready to flow through the shape insertion path and then into Konva and Pixi renderers.

The next step is to give each shape its own geometry instead of reusing the same base type.

Supabase flow

Reads and writes

The library table loads records from block_library_records and upserts by slug. That keeps the client flow simple and lets RLS control the rules.

Schema

The schema includes indexes for category, source tier, and updated time, plus safe status checks. It is ready to apply in Supabase.
